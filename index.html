ValuePick — 가치 투자 종목 발굴 서비스 (4인 팀 프로젝트)

GitHub

2026.06 — 2026.07

가치투자 지표 기반 종목 스크리닝 서비스. DART 재무제표, 공공데이터포털 주가, KRX 지수, 한국수출입은행 환율을 매일 자동 수집해 PER·PBR·ROE·Piotroski F-Score 등 투자지표를 계산하고, 다팩터 가중 스코어링으로 저평가 우량주 TOP100을 추천합니다. 개인 투자일지(매수/매도 기록, 손익 관리) 기능을 함께 제공합니다.

GitHub으로 협업했으며, 외부 데이터를 모아 투자지표를 계산하는 부분은 다른 팀원이, 종목 상세조회·재무제표 조회·관심종목·금융 뉴스 자동 수집 기능은 본인이 맡아 진행했습니다.

담당 기능

종목 상세 조회

역할회사 기본정보, 최신 시세, 투자지표, 재무제표까지 흩어져 있던 정보를 하나의 화면에서 한 번에 볼 수 있도록 구현했습니다.

성과여러 번 나눠 불러오던 정보를 요청 한 번으로 받아오도록 만들어, 종목 상세 페이지가 끊김 없이 빠르게 뜨도록 했습니다. (종목 검색·필터링 기능은 다른 팀원 담당)

인사이트화면에 필요한 데이터를 그때그때 따로 조합하면 나중에 코드가 지저분해질 것 같아, 처음부터 서버에서 미리 정리해 내려주는 방식을 선택했습니다.

재무제표 조회

역할팀원이 DART 공시 자료로 모아둔 재무제표 데이터를 종목별로 조회해 보여주는 기능을 처음부터 설계하고 구현했습니다.

성과데이터를 모으는 부분과 보여주는 부분을 분리해서 만들어, 나중에 데이터 수집 방식이 바뀌어도 화면 표시 기능은 그대로 유지되는 구조를 만들었습니다.

인사이트데이터를 모으는 일과 보여주는 일은 담당자도 다르고 바뀌는 시점도 다르다고 판단해, 처음부터 역할을 나눠 설계했습니다.

투자지표 차트 (수익·자산 추이)

역할연도별 매출·이익 변화(수익 추이)와 자산·부채·자본 변화(자산 추이)를 탭으로 바꿔가며 볼 수 있는 그래프를 만들었습니다.

성과이미 불러온 재무제표 데이터를 그대로 활용해 별도로 서버에 다시 요청하지 않고도, 탭 전환만으로 두 그래프를 즉시 볼 수 있게 만들었습니다.

인사이트매출이나 이익 하나만 보면 회사 상태를 제대로 판단하기 어렵다고 생각해서, 자산과 부채 흐름도 함께 볼 수 있도록 그래프를 하나 더 추가했습니다.

금융 뉴스 자동 수집

역할네이버 금융에 올라오는 종목별 뉴스를 자동으로 가져와 보여주는 기능을 전담해 구현했습니다.

성과매시 정각마다 자동으로 새 뉴스를 수집하도록 만들었고, 실제 운영 환경에서 신규 뉴스 20건이 정상 수집되는 것을 확인했습니다. 요청 사이에 짧은 대기 시간을 둬서 안정적으로 수집되도록 했습니다.

인사이트너무 빠르게 반복 요청하면 차단될 수 있다고 판단해 요청 간격을 뒀고, 같은 뉴스가 중복 저장되지 않도록 처리했습니다.

관심종목 기능 (화면과 서버 모두 담당)

역할로그인한 사용자가 원하는 종목을 관심종목으로 등록·삭제·조회할 수 있는 기능을 화면부터 서버까지 전부 구현했습니다.

성과종목 개수만큼 반복해서 데이터를 조회하던 방식을 한 번의 조회로 합쳐 속도를 개선했고, 존재하지 않는 종목을 등록하려 하거나 이미 등록된 종목을 중복 등록하는 등 예외 상황도 문제없이 처리되도록 만들었습니다.

인사이트뒤로가기로 페이지를 다시 열었을 때 화면이 최신 상태로 갱신되지 않는 문제를 직접 찾아내, 페이지가 다시 보일 때 데이터를 새로고침하도록 고쳐 해결했습니다.

트러블슈팅

  • 관심종목 등록이 계속 실패하던 문제 — 서버에 요청을 보낼 주소가 중복으로 조합되면서 잘못된 주소로 요청이 나가고 있던 것이 원인이었습니다. 주소를 만드는 부분을 한 곳에서만 처리하도록 정리해 해결했습니다.
  • 로그인은 되는데 관심종목 등록이 안 되던 문제 — 로그인 정보를 다시 불러오는 과정에서 사용자를 구분하는 값이 채워지지 않고 있던 것이 원인이었습니다. 로그인 정보를 복원할 때 해당 값을 함께 채우도록 수정해 해결했습니다.

FotData — 해외축구 데이터 분석 및 예측 서비스 (개인 프로젝트)

GitHub

2026.07 — 2026.08

EPL·라리가·분데스리가·세리에A·리그1·UEFA 챔피언스리그의 경기 데이터를 football-data.org API로 매일 자동 수집해 팀 성적, ELO 레이팅, 경기 승률·시즌 순위·득점왕 예측까지 제공하는 축구 분석 서비스입니다. 기획부터 백엔드 API 설계, 프론트엔드 UI, 배치 스케줄링까지 전 과정을 혼자 설계하고 구현했습니다.

단순 데이터 조회를 넘어, 체스 레이팅 시스템인 ELO를 축구 도메인에 맞게 변형(홈 어드밴티지 보정, 무승부 확률 모델링)해 팀 실력을 정량화하고, 이를 기반으로 몬테카를로 시뮬레이션을 2,000회 반복해 시즌 순위를 확률적으로 예측하는 분석 로직을 직접 설계했습니다.

담당 기능

경기 목록 · 순위표 조회

역할리그·시즌·라운드별 경기 결과, 팀 득점/실점 순위, 선수 개인 득점 순위, 팀 상세 성적(승무패·홈원정 득실차·최근 폼)을 조회하는 API와 화면을 전부 구현했습니다.

성과실제 6개 대회의 2025-2026 시즌 전체 데이터를 동기화해 검증했고, 이 과정에서 UEFA 챔피언스리그의 토너먼트 구조(matchday가 없는 경기)와 리그1의 몰수패(AWARDED) 상태값 등 대회별 데이터 정합성 버그를 직접 발견해 수정했습니다.

인사이트같은 라운드 번호라도 시즌이 다르면 다른 경기라는 점을 놓쳐 데이터가 섞이는 버그를 겪은 뒤, 리그+시즌+라운드 조합이 있어야 경기를 유일하게 특정할 수 있다는 걸 체감했습니다.

ELO 레이팅 시스템

역할체스에서 쓰이는 ELO 레이팅 공식을 축구에 맞게 변형해 팀별 실력 지표를 계산하는 로직을 설계했습니다. 홈 어드밴티지 보정값을 더하고, 경기 결과가 확정될 때마다 두 팀의 레이팅을 자동으로 갱신합니다.

성과시즌 구분 없이 누적되는 전역 지표로 설계해, 시즌이 바뀌어도 팀 실력의 흐름이 끊기지 않고 이어지도록 했습니다. 실제 2025-2026 시즌 데이터로 계산한 결과 상위권 팀(맨시티, 아스날 등)이 실제 성적과 일치하는 순서로 나오는 것을 확인했습니다.

인사이트새로 생성되는 경기가 처음부터 '종료' 상태로 들어오면(과거 시즌 동기화 시) 레이팅 갱신 로직이 이를 놓치는 버그를 발견해, 기존 경기 존재 여부를 먼저 확인하도록 순서를 바꿔 해결했습니다.

경기 승률 예측

역할두 팀의 ELO 차이를 승/무/패 확률로 변환하는 예측 모델을 구현했습니다. 체스식 승률 공식은 무승부가 없어, 실력 차이가 클수록 무승부 확률이 낮아지도록 별도의 보정 공식을 추가했습니다.

성과동일 실력 팀 간 대결에서는 홈팀이 근소하게 유리하고, 실력 차이가 커질수록 무승부 확률이 자연스럽게 줄어드는 것을 단위 테스트로 검증했습니다.

인사이트단순히 이길 확률만 보여주기보다, 왜 그런 결과가 나왔는지 설명 가능한 지표(ELO 차이)를 기반으로 삼아야 사용자가 예측 결과를 신뢰할 수 있다고 생각했습니다.

시즌 순위 · 득점왕 예측

역할남은 시즌 전체 일정을 ELO 승률로 2,000회 몬테카를로 시뮬레이션해 팀별 평균 순위·우승 확률·강등 확률을 계산했습니다. 득점왕은 지난 시즌 경기당 득점률을 다음 시즌 예상 경기 수에 대입해 추정했습니다.

성과강등된 팀이 새 시즌 순위 예측에 잘못 포함되는 버그와, 리그전 방식으로 설계한 득점왕 예측 로직을 경기 수 체계가 다른 토너먼트 대회(UEFA 챔피언스리그)에 그대로 적용했을 때 비현실적인 값이 나오는 문제를 각각 발견해, 예측 대상 팀을 실제 시즌 픽스처 기준으로 다시 산정하고 토너먼트 대회는 이 예측에서 제외하도록 수정했습니다.

인사이트같은 계산 로직이라도 대회 방식(리그전 vs 토너먼트)에 따라 전제가 달라질 수 있다는 것을, 실제 데이터로 검증하는 과정에서 발견하고 대응했습니다.

관리자 API 및 자동 동기화 스케줄러

역할외부 API 데이터를 리그별로 동기화하는 관리자 전용 API와, 하루 2회 6개 대회를 자동으로 동기화하는 배치 스케줄러를 구현했습니다. 관리자 API는 별도 인증 필터로 보호했습니다.

성과무료 API 티어의 호출 제한에 걸리지 않도록 요청 간 최소 대기시간을 둔 레이트 리미터를 직접 구현했고, 신규/기존 경기를 구분해 처리하는 upsert 로직으로 중복 없이 안전하게 반복 동기화할 수 있도록 만들었습니다.

인사이트관리자 기능이라고 인증을 소홀히 하면 안 된다고 판단해, 요청 헤더의 키 값이 비어있으면 무조건 차단하는 fail-closed 방식으로 설계했습니다.

트러블슈팅

  • 같은 라운드에 다른 시즌 경기가 섞여 조회되던 문제 — 경기를 리그+라운드로만 구분하고 시즌을 구분하지 않아 발생했습니다. 시즌 컬럼을 추가하고 조회 조건에 포함시켜 해결했습니다.
  • 과거 시즌 동기화 시 팀 성적이 갱신되지 않던 문제 — 새로 생성되는 경기가 이미 '종료' 상태로 만들어지면서, '새로 종료된 경기인지' 판단하는 로직이 이를 놓치고 있었습니다. 기존 경기 존재 여부를 먼저 조회해 판단 기준으로 삼도록 순서를 바꿔 해결했습니다.
  • 경기 승률 예측·상대전적 조회에서 같은 팀을 양쪽에 선택해도 결과가 나오던 문제 — 경기 예측은 두 팀이 동일하면 ELO 차이가 0이라 계산은 되지만 의미 없는 확률이 나왔고, 상대전적도 같은 팀끼리는 존재할 수 없는 경기인데도 "0승 0무 0패"라는 결과가 그대로 표시됐습니다. 두 기능 모두 백엔드에서 동일 팀 요청을 차단하고, 프론트에서도 같은 팀을 선택하면 안내 문구를 보여주도록 이중으로 방어했습니다.
  • 강등된 팀이 새 시즌 순위 예측에 포함되던 문제 — 팀의 리그 소속 정보가 고정값이라 승격·강등을 반영하지 못했습니다. 예측 대상을 리그 소속 팀 전체가 아니라 실제 해당 시즌 경기 일정에 등장하는 팀만으로 한정해 해결했습니다.
